# 티켓시그널

이 저장소는 티켓시그널 애플리케이션 소스와 중간고사 MVP 제출 자료를 함께 제공합니다. 기획 대비 변경 이유와 실제 검증 결과·증거도 포함합니다.

NOL 티켓, 티켓링크, 멜론티켓, YES24의 공개 오픈예정 공지를 수집하는 웹서비스입니다. 한국시간 오늘부터 13일 뒤까지 총 14일의 티켓 오픈 일정을 표시합니다. 선예매와 일반예매는 별도 일정입니다. 날짜 미정, 비공개, 원본에서 이미 제외한 일정의 완전성은 보장하지 않습니다.

이메일·관심 키워드는 서버에 저장하며, 메일의 확인 버튼을 눌러야 구독이 활성화됩니다. 오픈 24시간 전부터 매시간 확인해 미발송 관심 공연을 안내하고, 메일의 해지 링크에서 서버 정보를 삭제할 수 있습니다. 기존 브라우저 데모는 자동 이전하지 않습니다. [실제 이메일 구현과 운영 제한](docs/email-alerts.md)을 참고하세요.


## 기획안과 현재 구현의 차이

최종 구현 반영일: 2026-10-28. 비교 대상은 「중간고사 MVP 기획안3 — 티켓 레이더」의 5개 슬라이드와 현재 소스입니다. 구현 내용은 현재 소스와 실행 기록을 기준으로 정리했습니다. 실제 공연 알림 수신과 중복 방지를 검증했으며, 예약 실행 자체의 성공 여부는 수동 검증과 구분합니다.

- 공개 데모: https://ticket-signal.kmu-mba-1095.chatgpt.site
- 해결하려는 문제: 공연 관람객이 네 예매처를 각각 방문해 오픈 일정을 확인해야 하는 불편과 예매 일정 누락.

## 이메일 알림 동작

이메일과 관심 키워드를 입력하고 확인 메일의 버튼을 누르면 구독이 활성화된다. 서버는 매시간 정각에 앞으로 24시간 이내 열리는 공연을 확인해 키워드가 맞는 미발송 일정을 안내한다. 설정 변경도 이메일 재확인 후 반영하며, 확인 완료 화면과 알림 메일의 해지 링크에서 구독을 종료할 수 있다.

기존 매일 한국시간 06시 데이터 수집과 매시간 이메일 알림 예약을 활성화했다. 실제 운영 알림의 발송·수신·중복 방지는 수동 실행으로 검증했다. 정확히 24시간 전 도착을 보장하지 않으며, 뒤늦게 등록하거나 발견한 일정은 오픈 전 다음 실행에 알린다. 발송 한도와 오류 처리 등은 [이메일 구현·운영 안내](docs/email-alerts.md)에 정리했다.

## 로컬 실행 방법

Node.js **22.13 이상**과 npm, Git이 필요하다. Linux/WSL에서 검증했다. 로컬 D1·R2 에뮬레이터를 사용하므로 Cloudflare 계정이나 Gmail 인증 없이 목록과 관심 저장을 실행할 수 있다.

```bash
git clone https://github.com/tmdguq2002/ticketsignal.git
cd ticketsignal
npm ci
npm test
npm run build
cp .env.example dist/server/.dev.vars
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_lucky_scrambler.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_perpetual_pretty_boy.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_rapid_felicia_hardy.sql
npm start -- --port 4173
```

브라우저에서 **http://127.0.0.1:4173**을 연다. 마이그레이션 명령은 새 로컬 DB에 한 번 실행한다. `dist/server/.dev.vars`의 인증값은 기본 실행 시 비워 두며, 메일 모드는 `disabled`로 유지한다. `.env.example`은 설명용 템플릿이고 빌드 후 로컬 Worker가 읽는 파일은 `dist/server/.dev.vars`다. 재빌드하면 이 파일이 사라질 수 있으므로 필요 시 다시 복사한다. Windows에서는 WSL에서 위 명령을 실행할 수 있다.

초기 데이터는 `server/initial-snapshot.json`의 2026-10-24 수집본이다. 조회 시 실제 오늘 기준 14일 필터를 적용하므로 시간이 지나면 목록이 줄거나 비어 있을 수 있다. 이는 과거 날짜를 현재 일정으로 꾸미지 않기 위한 동작이다. 고정 데이터 기반 필터·정렬·통합 검증은 `npm test`로 재현할 수 있다.

관심 저장 HTTP 검증은 서버를 켠 상태에서 다른 터미널에서 실행한다. 현재 범위에 일정이 한 건 이상 있어야 하며 검증용 관심은 종료 시 삭제한다.

```bash
node tests/interest-http-check.mjs http://127.0.0.1:4173
```

개발 중 화면 수정은 `npm run dev`로 실행할 수 있다. 제출 재현은 위 빌드·로컬 Worker 실행 절차를 기준으로 한다. 로컬 상태는 `.wrangler/state`에 보관된다. 로컬 데이터를 초기화하려면 서버를 종료한 뒤 이 폴더를 삭제하고 마이그레이션을 다시 실행한다.

### 운영 환경과 로컬의 차이

- 운영은 Cloudflare D1(`DB`)·R2(`BUCKET`)와 Sites의 인증된 소유자 갱신 도구를 사용한다. `.openai/hosting.json`의 프로젝트 ID는 비밀 키가 아니며 접근 권한을 부여하지 않는다.
- 매일 한국시간 06시 수집과 매시간 알림 작업은 기존 서비스의 외부 예약 설정이다. 저장소를 복제하거나 로컬 서버를 켜는 것만으로 예약이 생성되지 않는다.
- `REFRESH_OWNER_EMAIL`과 검증된 호스팅 인증이 있어야 운영 갱신을 허용한다. 별도 호스팅에서는 인증 헤더를 외부 사용자가 임의로 주입하지 못하도록 신뢰 경계를 구성해야 한다.
- 기본 환경 예시는 Gmail 발송을 비활성화한다. 실제 운영에는 Gmail OAuth 변수와 구독 서명 비밀값·서비스 origin이 필요하다. 빈 설정으로 실행하면 메일은 전송되지 않는다.
- 외부 예매처의 차단·구조 변경·공지 삭제로 수집이나 링크 확인이 실패할 수 있다.

## 에이전트 작업 기록

사람은 기능 범위와 우선순위를 정하고, Codex는 구현·검증·문서화를 수행했다. [전체 협업 기록](docs/agent-work-log.md)에 주요 요청과 결과, 사람이 수정한 내용, 실패 원인과 복구 근거를 연결했다.

| 평가 요소 | 실제 협업 사례 |
|---|---|
| 에이전트에게 시킨 주요 요청 | 네 예매처 통합, 14일 일정, 로고·포스터·개별 링크, 공연 통합·필터·정렬, 검증과 소스 공개 |
| 사람이 확인하거나 고친 것 | 변경 이유를 ‘요청에 따라 추가’에서 ‘포스터로 공연을 한눈에 식별’ 등 사용자 편익으로 수정하도록 피드백. Gmail 선택과 구현 우선순위 결정, 구독 확인 버튼 클릭 및 실제 공연 알림 수신 확인 |
| 막힌 곳과 복구 | 멜론의 페이지 중복 때문에 갱신 실패 → 중복 행 제외와 회귀 테스트 추가 → 수동 갱신으로 네 예매처 정상 확인. 브라우저 라이브러리 누락도 개발 환경 보완 후 검증 재개 |

테스트와 화면 검증은 에이전트가 수행했고, 사용자는 구독 확인 버튼 클릭과 실제 공연 알림 수신을 확인했다. YES24 상세 페이지는 자동 브라우저 접속 차단으로 본문 확인이 제한됐다. 매시간 예약의 실제 실행 성공과 운영 환경의 구독 해지는 이번 수동 검증 범위에 포함하지 않았다.

## 실패한 예매처 자동 재시도

매시 45분에 실패 예매처만 확인한다. 실패 후 최소 30분, 재실패 후 60분·120분을 기다린 다음 예약 실행에 재시도하며 최대 3회 후 다음 전체 수집까지 보류한다. 정상 예매처와 이전 정상 데이터는 유지한다. 05:45~06:15에는 재시도를 쉬어 오전 6시 전체 수집을 우선한다. 대상이 없으면 원본 사이트에 요청하지 않는다. [동작 규칙과 검증 범위](docs/source-retries.md).
