# 8번 · 에이전트 협업 작업 기록

작성일: 2026-10-27 · 프로젝트: 티켓시그널 · 구현 지원 에이전트: Codex

이 문서는 평가 항목 ‘에이전트에게 시킨 주요 요청, 사람이 확인하거나 고친 것, 막힌 곳과 복구한 방법’에 대응한다. 주요 요청과 사람의 수정은 실제 작업 대화에 근거하고, 구현·실행 결과는 저장소 문서·로그·화면에 연결했다. 초기 요청의 정확한 일시는 따로 기록되어 있지 않아 임의의 날짜를 붙이지 않았다.

## 역할과 책임

**사람은 문제와 범위, 우선순위, 표현을 결정했다.** 네 예매처 통합, 이메일·관심 키워드 입력 방식, 초기 데모 범위, 공개 서비스와 저장소, 데이터 표시 조건을 정했다. 이후 평가표와 기획안을 제시하고 단계별 진행을 지시했으며, 변경 이유를 사용자 관점으로 고치도록 피드백했다.

**Codex는 구현과 검증을 수행했다.** 수집·통합·필터·정렬·관심 저장 코드를 작성하고, 배포 상태·브라우저·API·자동 테스트로 결과를 확인했다. 발견한 오류를 수정하고 재현 절차와 증거를 문서화했다. 아래의 테스트·화면 확인은 에이전트 실행 결과이며 사람이 직접 테스트했다고 바꿔 쓰지 않았다.

기획안의 에이전트 이름은 Hermes였으나 실제 작업은 Codex와 진행했으므로 구현 기록에는 Codex를 사용한다.

## 결과를 확인한 방식

1. **단위·저장 테스트:** 날짜 경계, 공연 통합, 정렬, 관심 중복 집계, 수집 오류 처리를 검사했다. 2026-10-27 재실행 결과 35개 통과, 실패 0개. [로그](evidence/automated-tests-2026-10-27.txt).
2. **브라우저·API 검증:** 실제 화면에서 통합 상세·필터·관심 저장과 새로고침 유지·해제를 확인하고 API의 건수·기간을 비교했다. [제출용 검증 4건](validation-summary.md).
3. **독립 실행 검증:** 기존 의존성·DB·운영 인증을 복사하지 않은 별도 폴더에서 README 명령으로 설치·빌드·로컬 API와 관심 저장을 확인했다. [재현 기록](reproduction.md).

검증용 관심 등록은 종료 후 정리했다. 문서의 건수는 해당 시점의 수집본 기준이다. 예를 들어 운영 170개 일정과 로컬 초기 스냅샷의 121개 일정은 서로 다른 데이터이며, 관심 수 테스트에 사용한 등록을 실제 이용자 반응으로 설명하지 않는다.

## 제출 시 사용할 요약문

> 티켓시그널은 사람이 서비스 범위와 우선순위를 정하고 Codex가 구현·검증을 지원하는 방식으로 개발했다. 사람은 네 예매처 통합, 14일 범위, 로고·포스터와 개별 링크, Gmail 방향을 결정했으며, 변경 이유를 단순한 요청 반영이 아닌 사용자의 탐색 편익으로 수정하도록 피드백했다. Codex는 공연 통합·필터·정렬·관심 저장을 구현하고 실제 화면·API·테스트 결과를 기록했다. 멜론 페이지 중복으로 수집이 실패했을 때 중복 처리와 회귀 테스트를 보완해 운영 갱신을 복구했다. 공개 소스는 별도 폴더에서 설치·빌드·실행을 확인했다. 실제 이메일 발송과 YES24 상세 화면의 일반 브라우저 확인은 미완료로 남겼다.

## 기록의 범위

이 문서는 대화의 모든 메시지를 나열한 원문 로그가 아니라 주요 의사결정과 구현·검증 근거를 연결한 협업 기록이다. 대화 속 사용자 요청은 이 작업 세션을 근거로 옮겼으며 별도 공개 대화 원본은 첨부하지 않았다. 이메일 주소·인증정보는 기록에 넣지 않았다. 과거 계획 문서의 미완료 체크박스는 당시 상태를 담을 수 있으므로 현재 결과는 검증 문서와 이 기록을 함께 참조한다.
