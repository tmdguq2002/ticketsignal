# Gmail 발송 전환

사용자가 Brevo 대신 Gmail API를 선택했다. 기존 사이트는 공개 일정 API/R2, 소유자 전용 MCP 갱신 도구, 브라우저 전용 데모 구독을 제공한다.

## 선택과 범위
SMTP는 현재 호스팅에서 지원하지 않는다. Gmail API HTTPS와 소유자의 offline OAuth 승인을 사용한다. 수신자는 Google 로그인이 필요 없다. 메일 읽기 권한은 요청하지 않는다.

먼저 서버 전용 발송 모듈, 설정 상태 점검, 한글 MIME 및 실패 처리 테스트를 준비한다. 자격 증명과 발신 주소가 아직 없으므로 이 단계에서는 실제 전송하지 않는다. 기존 구독 폼은 데모 표시를 유지한다.

후속 활성화에는 발신 Gmail 주소, Google Cloud OAuth 클라이언트 및 계정 소유자 인증이 필요하다. 이어 서버 구독 DB, 이메일 확인, 해지, 중복 방지 발송 큐와 스케줄을 연결한다. 기존 데모 구독을 실제 구독으로 자동 이전하지 않는다. 현재 데이터 갱신 스케줄은 메일 발송하지 않는 상태를 유지한다.

## 구현 결정
자격 증명은 Sites 서버 비밀 환경 변수에만 저장한다. Gmail API 오류 본문과 토큰은 반환/로그하지 않는다. 전송 API에 대한 자동 재시도는 하지 않는다. 네트워크 오류는 전송 여부 불명으로 분류해 중복 메일을 방지한다. 시작 단계의 발송 모드는 disabled/test이며 test 모드는 발신자 본인에게만 허용한다. 실제 구독 발송 모드는 구독 검증과 큐 구현 후 추가한다.
